# Админка приглашения

Откройте `/admin` на своём сайте. Без настройки пароля вход отключён. Обычное приглашение работает без админки и без переменных окружения.

Редактор позволяет менять тексты, даты и адрес; добавлять, удалять и переставлять подарки; загружать их изображения и изображение окна о подарках. Напитки и видео пока редактируются в коде.

## Подключение

1. Создайте **свою копию репозитория** кнопкой Use this template и подключите её к автоматическому деплою хостинга.
2. Создайте fine-grained токен GitHub: доступ **только к своей копии**, разрешение **Contents: read and write**. Не давайте токену доступ ко всем репозиториям. Инструкция: [GitHub personal access tokens](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens).
3. На хостинге добавьте серверные переменные из таблицы. Локально можно скопировать `.env.example` в `.env.local`, заполнить и перезапустить приложение.

| Переменная | Значение |
| --- | --- |
| `ADMIN_PASSWORD` | Собственный длинный пароль, минимум 12 символов |
| `ADMIN_SESSION_SECRET` | Независимый случайный секрет, минимум 32 символа |
| `ADMIN_ALLOWED_ORIGINS` | Точный публичный адрес сайта с `https://`, без завершающего `/`. Несколько адресов — через запятую. Локально: `http://localhost:3000` |
| `INVITATION_GITHUB_TOKEN` | Fine-grained токен с Contents: write |
| `INVITATION_GITHUB_REPOSITORY` | `владелец/репозиторий` вашей копии |
| `INVITATION_GITHUB_BRANCH` | Ветка публикации, обычно `main` |

Ни одна из переменных не должна начинаться с `NEXT_PUBLIC_`. Не коммитьте `.env.local`, пароль или токен. Секрет сессии можно сгенерировать локально:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Вход защищён подписанной cookie на сутки, проверкой Origin и ограничением попыток. Ограничение действует в пределах одного процесса; для публичной production-админки настройте также rate limit на стороне хостинга/прокси. При смене пароля или секрета существующие сессии прекращают работать. Используйте HTTPS.

## Редактирование и публикация

1. Войдите и нажмите **Загрузить из GitHub**: редактор получит последнюю версию выбранной ветки.
2. Внесите правки. Кнопка **Предпросмотр** показывает весь сценарий с черновиком и не публикует его.
3. Нажмите **Опубликовать**. Тексты и новые изображения сохранятся одним коммитом. Гости увидят их **после успешной пересборки сайта**.
4. Перед следующей публикацией снова загрузите версию из GitHub. При конфликте сохранение отклоняется, чтобы не затереть чужие правки.

При ручном деплое/VPS коммит не перезапускает сервер сам: подтяните обновления, пересоберите и перезапустите сайт либо настройте CI/CD. Защищённая ветка должна разрешать этому токену коммиты; редактор не обходит branch protection.

Черновики не сохраняются между обновлениями страницы. Загружайте PNG, JPEG или WebP до 15 МБ: браузер уменьшает их до 1000 пикселей, итоговый файл должен быть не больше 500 КБ. За публикацию — до 3,5 МБ содержимого; при необходимости публикуйте изображения партиями. Более строгие ограничения хостинга также действуют.

Изображения сохраняются в `public/uploads/`, настройки — в `content/invitation.json`. Удаление карточки не удаляет изображение и предыдущие версии из истории Git. Считайте все публикуемые материалы публичными; не загружайте секретные данные. Сам редактор не собирает ответы гостей.
